# Code and experimental-design audit of the supplied RAG reference

The supplied package is substantially more useful than our earlier fictional
visitor-guide pilot: it supplies real NQ questions, Wikipedia-derived retrieved
passages, targeted wrong answers, semantic retrieval scores, prompt-level
generator outputs, an explicit corruption-removal reference, and standardised
fusion. Its headline numbers should be treated as supplied results until their
provenance is independently established. The code contains no obvious direct
label feature in the main step-6 scorer, but several design shortcuts limit what
the high detection rates establish.

## What is valid in the main scorer

- Step 6 assigns each question to one of five folds. For test fold f, fold f+1 is
  validation and the remaining three are training. The test question's examples
  from every attack setting are excluded from fitting and calibration.
- `StandardScaler` is inside the training-fitted sklearn pipeline. This corrects
  our earlier pilot's unstandardised, saturated neural-score problem.
- Stealth is excluded from training settings. Its labels and downstream success
  are not used to choose the threshold. It is a genuine authored-family holdout,
  although one family cannot establish general adaptive robustness.
- The 95th-percentile threshold uses only no-attack validation passages, rather
  than attack success or the test labels. The deployed FPR on attacked pools is
  separately reported and need not equal the clean calibration rate.
- Features use passage content, supplied scores and peer similarities. The
  gold `is_adv` flag is a training/evaluation label; it does not enter the feature
  vector. Oracle filtering is the sole intentionally privileged baseline.
- Warming frozen guard/embedding caches with test texts is label-free inference,
  not fitting on the test distribution. It must still be described as cached
  frozen inference, with model revisions and representations pinned.

These claims refer to `step6_trust_scorer.py`, especially the feature construction
and fold masks around lines 225–271. They do not validate the separate step-5
dataset split or prove that every supplied output was generated by these files.

## Findings requiring correction or narrower interpretation

|---|---|---|
| Step-5 question split is violated | `step5_build_scorer_dataset.py` line64 forces every stealth sample to test, including questions allocated to train/validation | Do not use this file as evidence of question-disjoint training. Step6 does not read it, so this is not automatically leakage in the main scorer. |
| Step-5 artifact is stale | Independent data audit finds a different target-question collection in the supplied scorer dataset | Rebuild from the exact current targets and record file hashes. |
| Clean and attack scores come from different executions | Step3 preserves old clean scores but freshly encodes attacks; it only prints a ten-query discrepancy check and never aborts | Verify a pinned encoder against all target clean records, and recompute every compared score with one encoder. If scores differ materially, claim candidate-pool reranking rather than full-corpus reproduction. |
| Query grouping is not document grouping | Two genuine document IDs appear in different question folds | Report the small exact-document overlap. Do not claim strict document/topic holdout. Provide overlap-exclusion sensitivity if needed. |
| Density has an authored side channel | Five passages per question share the same question prefix, wrong answer and payload bank | Include score-only/density-only/content-only ablations, matched one-passage transfer, and benign redundancy controls. |

Whitespace escape variants can also tokenize identically. Keep the benchmark as a stated multirecord threat and report uniqueness. |
| Rules match the attack construction | Every naive payload uses one of three strings explicitly matched by the ten fixed regexes | Near-perfect known-template rule performance is expected and does not demonstrate learned semantic generalisation. Poison and stealth are essential separate results. |
| Supplied single-attack experiment refits | Notebook reruns step6 on `data_single` | This is a model trained for one-attack conditions, not transfer from five attacks. Freeze the five-attack heads and thresholds before evaluating one attack. |
| Supplied single texts are resampled | Step2's RNG consumes different numbers of draws when `adv_per_query` changes | Cardinality and template sampling change together. For a count-only comparison, keep the strongest retrieval-score attack from the same five texts. |
| NotInject check uses mostly unrelated inserted prompts | Step6 inserts two randomly sampled NotInject prompts in each query's pool and reports only aggregate flags | Report insertion ranks and distinct text counts. Low FPR on low-ranked unrelated text is not evidence of preserving relevant benign instructions. Use query-related benign controls. |
| Guard/model versions are unpinned | HF model names lack immutable revisions; fallback silently switches guard family | Pin exact checkpoints, save tokenisation caps, class mappings, loading information and file hashes. Never silently change models during a run. |
| Feature models are not saved | Step6 saves mean coefficients and rounded probabilities/thresholds, not each trained fold pipeline | Exact reproduction from those summaries is impossible. Save full per-fold scaler means/scales, weights, intercepts and thresholds. |
| Timing excludes the expensive defense | Step4 times selection from precomputed flags | `defense_ms≈0.01` is lookup/backfill cost, not neural scoring. The separate step6 measurement includes guard and embedding cost; its hardware remains unspecified. |
| Oracle is overstated | `defenses.py` calls corruption removal an upper bound | It is a privileged corruption-removal reference, not a formal bound on QA accuracy or ASR. Benign sources may still be wrong or contradictory. |
| Target match is not causal attack success | `answer_hit` performs a lowercased substring check | Recompute bounded/normalised matches and compare every attacked response with its paired clean baseline. Baseline wrong answers can satisfy the target without an attack. |

| Provenance is incomplete | Response rows have no model revision/backend/hardware/decoding manifest; notebook contains commands but no executed outputs | Supplied results can be reanalysed and attributed, but do not claim independent execution of a pinned 3B model. Run a fresh pinned generator for independent evidence. |

Step1's `--max_queries` also keeps all target questions and then appends N
nontargets; it is not a strict total-query limit. This does not affect the default
full extraction, but should be fixed before calling it a debug sample size.

## Interpretation of the supplied generator results

The independent data audit verifies prompt/context reconstruction and raw
substring metrics. The three oracle target hits are the same three questions
already producing target answers in clean contexts: New York Yankees, Michael
Jordan and Bill Belichick. They are full semantic target answers, not merely
short-number substring accidents. Therefore the oracle's 3% target-hit rate is a
baseline-error floor in these supplied outputs; it is not evidence of residual
corrupted passages passing an oracle.

ASR should be labelled **target-answer hit rate** for the supplied metric. A more
causal paired diagnostic is newly induced target output: target absent in that
gate's clean answer and present under attack. Also report clean→attacked correct
answer loss, not just target-hit changes. Accuracy and ASR can both be true if a
response contains both strings, so neither should be treated as mutually
exclusive without an exact-answer or answer-span check.

## Fresh follow-up frozen before new results

The implementation is `improved_experiment/run.py`; its protocol manifest is
written before inference. It does not modify the supplied source package.

1. Use the current 100 NQ targets and their original top20 clean candidates. Pin
   Contriever and DeBERTa-v3-base injection guard, download public weights once,
   and infer locally with CPU PyTorch. No paid APIs, account credentials or ONNX
   Runtime are used.
2. Recompute every clean and adversarial score with the same attention-mask mean
   pooled encoder and unnormalised dot product. Ranking clean passages uses
   title+text, as the source retriever did; attack passages use raw text. Check
   all 2,000 clean records against their supplied scores and retain the rowwise
   anchor discrepancies. Density uses the actual generator-visible text,
   normalised embeddings, and every other untrusted candidate.
3. Use five question folds with seed12. Each held-out model fits 60 questions,
   calibrates on 20 clean no-attack questions and tests 20 questions. Stealth is
   never used for fitting or threshold selection. Preserve the known small
   cross-question document overlap as an explicit limitation.
4. Fit standardised logistic heads with fixed C=1 and balanced classes. Compare
   rule, guard, score-only, density-only, context-only, guard+rule and fused.
   Rule/guard use their raw score; every head uses the same clean-validation
   quantile policy: method=`higher`, block strictly above the threshold, verify
   empirical validation FPR≤5%. Store full fold parameters, raw features,
   unrounded scores, decisions and serialised heads.
5. Freeze the five-attack heads before count transfer. Select one passage per
   family by highest retrieval score among the same five attacks, independently
   of detector labels or generator success. Also evaluate the supplied one-attack
   texts separately, explicitly naming their additional sampling shift.
6. Test benign controls with the same frozen heads. Query-echo controls prefix
   the literal question to five genuine clean passages while preserving their
   original factual text and compare with the same unmodified clean pool.
   Benign-mirror controls add exact copies of five genuine records. These are
   labelled counterfactual stress tests, not natural-frequency estimates.
7. As a separately declared exploratory extension, `aug_fused` appends only
   train-question benign query-echo controls as negative examples. Its validation
   rule remains clean-only. No validation/test control question enters fitting.
   This asks whether hard-negative augmentation can improve benign specificity
   while retaining attack recall. It does not alter the six primary generator
   gates.
8. Export the exact source RAG prompt under no filter, rule, guard, context,
   fused and corruption-removal reference for clean/poison/ignore/stealth on all
   100 questions. The independent generator owner runs one pinned free local
   causal instruct model with fixed greedy decoding. Report generator weakness,
   token caps, truncation, clean errors and paired new target inductions.

## What the earlier pilot remains useful for

Our earlier experiment demonstrates why naive combinations need diagnostics:
the old DistilBERT risk saturated on fictional writing, an unstandardised fusion
ignored neural variation, the strict benign-FPR budget selected reject-nothing
for the raw guard, and a tiny numeric-QA generator showed a ceiling. Those are
valid executed findings but weak main evidence for a RAG security project. They
should remain a brief development pilot or appendix, rather than be mixed into
the natural-data headline percentages. The new experiment improves data realism,
neural model provenance, calibration and downstream vulnerability measurement;
its authored attacks, limited candidate pool and one-family holdout still limit
claims about general robustness.
